# Registered advertising video inspection

`marketing_inspect_video` is a default-off, client-scoped READ operation. Enablement requires `LUMIN_PLATFORM_ENABLED=true` and `LUMIN_VIDEO_INSPECTION_ENABLED=true`, an exact registered `AD_VIDEO` and its `AD_ACCOUNT`, a selected USER credential and fresh grants, plus independently issued human eligibility evidence. `ads_read` is a conservative Lumin admission pack; the SDK field declaration does not establish a universal source-field permission minimum.

The provider contract uses the pinned official [AdVideo SDK reference](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/advideo.py) (`GET /VIDEO`, `id,source,length,status{video_status}`) and the corresponding [AdAccount reference](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/adaccount.py) (`GET /act_ACCOUNT/advideos`). Complete bounded account membership is mandatory: at most100 IDs, no next-page marker, one exact requested ID. Larger or incomplete libraries remain HOLD rather than implying absence or ownership. Registered authority is never derived from a CDN URL.

The private downloader accepts only the actual provider-returned HTTPS `*.fbcdn.net` source, public pinned DNS, no redirects, MP4 and at most16MiB. No Meta bearer token is forwarded to the CDN. Source URLs are never model outputs, persisted asset fields or audit fields. Local FFmpeg processes accept only pipe input/output ([official protocol controls](https://ffmpeg.org/ffmpeg-protocols.html)), with bounded memory, CPU concurrency, subprocess deadlines and response sizes. The current subset allows at most60seconds,1920pixels per side/2073600pixels total,60fps and one video plus optional audio stream. It generates1..4 actual JPEG frames, each at most640pixels per side/512KiB, and independently decodes every JPEG. No temporary media files are written.

The SDK wrapper must finish the READ and invoke its purpose-specific sealed current-response checkpoint after CDN downloading and decoding, before emitting metadata and JPEG image blocks. Member, selected credential ciphertext, grant, tenant/client and feature-flag changes must withhold output. The dedicated client additionally revalidates authorization after each asynchronous boundary. Generated frames remain ephemeral response content; no collection, TTL or private source cache is introduced.

Output reports observed duration, dimensions, frame rate, presence of an audio stream and sampled timestamps. `audio_transcribed=false` and `semantic_analysis_performed=false` are explicit. Observing an audio stream is not listening or transcription. This operation does not call Gemini or any paid analysis provider. No live-provider success or production activation has been established by local fake-provider tests.

`marketing_inspect_creative_video` adds a current fixed Creative read (`id,account_id,video_id`) from the pinned official [AdCreative reference](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/adcreative.py). Both the Creative and supplied Video must already be separately registered and authorized in the same client/account. The actual top-level Creative `video_id` must equal that registered Video before downloading. Missing or dynamic asset-feed/story references are HOLD; no undocumented reference inference or registry enrollment occurs. The sealed final snapshot includes every authority ancestor, including current Page/thumbnail grants where the Creative has them.

Metadata `frame_sampling_offsets_seconds` describes requested seek positions. These are approximate sample positions, not measured presentation timestamps. Each returned JPEG is nevertheless actually decoded from the downloaded provider source. The two original names `ads_get_video_media` and `ads_analyze_video` have explicit strict observational replacements using `video_id`/`frame_count`; old raw URLs, Gemini keys, prompt selectors, inline delivery controls and audio-analysis requests are rejected. This does not claim paid semantic video understanding.
