This source prepares a named optional provider; no vendor has been selected or activated and no paid request has been made. Enablement requires all three flags `LUMIN_PLATFORM_ENABLED`, `LUMIN_PAID_RESEARCH_ENABLED`, `LUMIN_APIFY_PUBLIC_ADS_ENABLED` plus a separately supplied secret `LUMIN_APIFY_API_KEY` and reviewed `LUMIN_APIFY_PUBLIC_ADS_POLICY_JSON`. This is separate from the approved Google infrastructure budget.

[Official synchronous dataset API](https://docs.apify.com/api/v2/actor-run-sync-get-dataset-items-post) supports `maxTotalChargeUsd`, fixed build, actor timeout, `restartOnError=false`, server projection and result limit in the same POST. Its documented run cap covers all run pricing models. The implementation performs this single request and no additional dataset/status API calls. Network loss, malformed receipt, secret echo or revoked authority leaves an uncertain once-only checkpoint; there is no resend, provider-idempotency claim or free idempotency lookup. `runTag` only binds returned observations to the approved request; it is not provider deduplication.

The distinct admission metadata says `providerHardRunCostCap=true`, `providerIdempotency=false`. The existing fully idempotent adapter admission is unchanged. A protected authenticated human review must approve the exact provider/build/query/country/provenance/count, run cap and client monthly ceiling, including the explicit risk checkbox. The shared service atomically reserves that ceiling and claims its durable attempt before any provider POST. Local quote/status/abort operations make no provider request; abort never claims provider cancellation. A local synthetic receipt ID is not a provider run ID.

Policy JSON contains only the exact actor/build identifiers, `maximumRunCostCents`1..500, `maximumResults`1..100, `approvedAt` and `expiresAt` (at most24hours). The policy and selected credential fingerprint bind the adapter version; mutation/configuration drift requires review and restart. Secrets remain outside JSON. Neither the display price nor the requested maximum result count substitutes for a run cap: public metadata currently reports a per-item event and an Actor-start event, and actual charges can vary with account pricing.

The response is encrypted on the scoped research job. Metadata-only public observations are incomplete and carry no account grants, competitor permissions, performance or outcome proof. Actual invoice cost remains unverified; job state is `UNKNOWN` with `ACQUISITION_COST_RECONCILIATION_REQUIRED`, while the private observation projection can be read only through the current atomic private-read checkpoint. The financial reservation remains in the permanent unresolved checkpoint until explicitly reconciled. Job/query/result personal provenance expires after7days or actual privacy deletion; deleting it does not release escrow or permit another attempt.

The community-actor acquisition slice returns bounded ad IDs, public advertiser/copy summaries and hashed provenance. It does not yet claim competitor media extraction, video understanding, current trend completeness or a live-provider acceptance test. The original secret-bearing Apify setters remain unavailable; named adapter configuration belongs to human credential onboarding.

## Precise output-schema limitation

The developer's public Store README sample image was visually inspected in the official Store on2026-10-16. It publishes camelCase `adArchiveID`, `pageID`, `pageName` and `isActive` with a `snapshot` object, but it is an older cropped example and does not show direct media URL paths. The specific current build OpenAPI exposes input/run schemas only. Source code is hidden. The reviewed repository baseline also accepts snake_case Ad Library records, but that is not current primary provider proof. The strict named adapter requests and accepts only the developer-published camelCase archive-ID shape and rejects the unverified snake_case shape. This is bounded observation parsing, not a claim that the current actor guarantees every example field.

Exact `snapshot.videos[].video_hd_url`/`video_sd_url` and image URL-path semantics therefore remain **UNVERIFIED for this named actor's current output contract**. Other actors' claims and baseline fixtures are not promoted to primary provider evidence. `media_extraction_supported=false` and `UNVERIFIED_ACTOR_OUTPUT_MEDIA_SCHEMA` remain explicit. A reliable actual provider-owned schema or independently reviewed real output sample is required before media extraction activation. This is a vendor-contract gate, not a claim that Meta generally forbids media or that merely adding credentials completes it.

Locally derived dossiers and copy frequencies operate only on the actual bounded returned sample. They state exact returned/distinct counts and literal copy-term prevalence, `complete=false`, `market_trends_verified=false`, `temporal_comparison_performed=false` and `performance_verified=false`. They do not infer winning ads, spend, conversion performance, market share or time trends from missing/unrepresentative observations.

Requested video sampling offsets are approximate seek positions, not measured presentation timestamps.

`meta_research_job_media` accepts only client and existing job IDs. It consumes a scoped, opaque decoded cache entry with a strict 60-second lifetime and eight-entry/16-MiB capacity. A current atomic private-read checkpoint verifies the exact encrypted job, actor, approver, membership indices and privacy/lifecycle state after cache loading, immediately before JPEG output. Expiration, consumption or withdrawal produces a hold; it never refetches, reruns the actor or releases the unresolved financial reservation. Support metadata does not promise that an ephemeral cache entry remains available.

Research tools include prepare, run, status, refresh, results, abort, cost reconciliation and ephemeral media, with the later temporal comparison and scoped saved-acquisition list described below. Dossiers and literal copy frequencies remain bounded observed-sample summaries, not verified market trends, ad performance or completeness. Local fake-provider tests exercise the real JPEG/MP4 decode and native MCP image path; they establish engineering behavior, not paid-provider or staging acceptance.

Privacy and cache lifetime are distinct: deleting or revoking a research job immediately prevents authorized output through the current database/identity checkpoint. A previously decoded public competitor frame may remain in process RAM until the bounded cache timer expires (at most60 seconds) or it is consumed/discarded. A database deletion receipt does not certify instantaneous process-memory erasure. Frames and provider media URLs are never persisted to the research database or copied into client Meta asset grants.

## Two-acquisition temporal comparison

`meta_research_compare_jobs(client_id, earlier_job_id, later_job_id)` compares two existing incomplete PUBLIC acquisitions with identical request/query/country/result bound, named provider/build and reviewed acquisition policy. Its two timestamps are actual local run-start times, not Meta event timestamps. It reports newly observed IDs, IDs not present in the later bounded sample, retained/changed copy and literal term-count deltas. Absence is not proof an ad stopped running; no market share, spend, delivery, causal or performance inference is made.

The read performs no paid operation, provider status lookup, refresh, media refetch or new cost approval. Archived receipts remain readable with the paid vendor disabled, subject to active platform authority. One atomic Memory/Firestore checkpoint checks BOTH exact encrypted jobs, requests/receipts, original actors, consumed approvals, current approvers, membership indices and privacy/lifecycle state. Platform/auth-app drift and the bounded read deadline are rechecked after the final await. Expired, incompatible or withdrawn input yields HOLD. The comparison tool is a distinct read-only registration; it does not inherit the single-job schema or start another acquisition.

## Saved public-acquisition metadata list

`meta_research_list_public_acquisitions(client_id, limit?)` is the tenth research control, bounded to 1–25 selected saved PUBLIC acquisitions in UNKNOWN financial-reconciliation state. It excludes unattempted/non-acquisition/Gemini jobs, expired jobs and missing receipts. It reports only job IDs, provider identity, state, local timestamps and cost-reconciliation metadata; it returns no query, copy, ciphertext, actor identity, provider run reference or media. It never calls the paid provider to enumerate runs and always reports `complete=false`.

A single atomic Memory/Firestore checkpoint checks the exact selected encrypted jobs, consumed approvals, original actors/approvers and their current global indices/privacy/lifecycle state. An empty response still requires an active scoped reader and identity checkpoint. At most 105 rows and 4 MiB canonical UTF-8 snapshot are accepted; oversized snapshots hold and require a lower limit. Auth-app/platform/deadline are checked again after the final await. No cost approval or new research attempt is created by this read.
