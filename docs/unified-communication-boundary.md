The V1 unified communication boundary is represented by `communication-model.ts`: Channel, scoped Conversation, Participant, Message, Attachment, derived ThreadState, and reserved local HandoffState. Messenger, Instagram DMs and WhatsApp remain distinct channels. Provider-native message/conversation/participant IDs are retained; they are never converted into each other's IDs. All records carry exact tenant/client/app/asset scope, an authenticated-read/signed-webhook/accepted-send provenance category, source digest, observation timestamp and expiry. Private content uses an opaque reference rather than copying message text or contact details into model-facing metadata.

The derived thread state reports only what the bounded authorized observation establishes: a known inbound message with no later observed outbound, an observed outbound after an inbound, no observed inbound, or unknown. Equal timestamps and unknown direction remain unknown. A send receipt is not read/delivery proof. Duplicate IDs, cross-client/channel/asset/conversation substitutions and stale provenance are rejected. Provider-complete history claims are intentionally unsupported by this bounded reducer.

Current local signed-event inbox metadata lacks sender, recipient and native conversation identity. The adapter preserves the native message ID and digest but marks direction UNKNOWN and conversation ID null; it cannot turn these events into an unanswered-DM claim. Real product-specific authorized conversation/message readers remain the content boundary. WhatsApp webhook ingestion is not a retrospective inbox API. The optional higher-level unanswered-message example remains gated until a channel-specific trusted direction/history adapter supplies those facts. This limitation is engineering integration still to be completed, not an App Review restriction.

HandoffState reserves an explicit local operator-workflow provenance and revision. No automated AI handoff, LeadGate coupling, assignment mutation, outbound send or customer-data export is enabled by this model. A future adapter must preserve the same client authorization, private-content retention and provenance and must obtain separately reviewed operator authority before changing local handoff state.
