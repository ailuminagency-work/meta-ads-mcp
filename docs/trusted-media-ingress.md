# Trusted JPEG intake and human review

This runtime is disabled by default. It receives JPEG bytes from a configured trusted storage adapter, performs real bounded pixel decoding, discards the bytes, and stores an encrypted review proposal. It never publishes content or creates a grant during intake. A signed adapter assertion does not establish that an arbitrary external URL contains those bytes: the approved adapter must control the configured immutable CDN and guarantee that the content-addressed URL serves the exact decoded digest for the lifetime of the publication request. Do not configure a general-purpose or mutable host as this adapter.

Enable only after configuring `LUMIN_PLATFORM_ENABLED=true`, `LUMIN_MEDIA_INGRESS_ENABLED=true`, `TOKEN_ENCRYPTION_KEY`, `SESSION_COOKIE_SECRET`, the provider's exact `META_APP_ID` or `INSTAGRAM_APP_ID`, and `LUMIN_MEDIA_INGRESS_PROFILES_JSON`. Each profile contains server-owned `id`, `tenantId`, `clientId`, `operatorId`, `connectionId`, numeric `accountId`, numeric `appId`, provider (`META_INSTAGRAM_LOGIN`, `META_INSTAGRAM_FACEBOOK_LOGIN`, or `META_FACEBOOK_PAGES`), `secretReference`, `allowedHost`, and `enabled`. References must match `LUMIN_MEDIA_INGRESS_KEY_[A-Z0-9_]{1,64}`; referenced environment values must be independent 32-byte hex HMAC keys. Never include key values in JSON, logs or source control. Each profile must use its own secret reference. Page profiles additionally require explicit `purpose:"facebook_content_publishing"`; Instagram profiles permit only `instagram_content_publishing` (the backwards-compatible default). `allowedHost` is one exact public HTTPS CDN hostname, with no wildcard, path or port.

The adapter sends JSON to `POST /platform/media/ingress/{profileId}` with `jpeg_base64`, `url`, `ai_generated`, `immutable:true`, and `rights:{granted:true,purpose:"instagram_content_publishing",checked_at,expires_at}`. For a Page profile the signed rights purpose must instead be `facebook_content_publishing`; a mismatched Instagram purpose is rejected before staging. The exact purpose persists in the enrolled source evidence. Rights timestamps are milliseconds, current within five minutes, with expiry no more than five minutes after checking. The URL path must include the exact SHA-256 content digest. URL credentials, credential-like query parameters, private IP literals, local hosts, fragments and redirects via a different supplied host are rejected. The intake does not fetch arbitrary URLs. Signed bytes must be canonical base64; JPEGs are limited to 8 MiB, supported Instagram dimensions and aspect ratio. Actual `jpeg-js@0.4.4` decoding runs in isolated workers with strict decoding, bounded memory, resolution, concurrency and a two-second deadline; MIME names or file extensions cannot establish JPEG provenance.

Headers are `x-lumin-timestamp` (13-digit current milliseconds), `x-lumin-delivery` (unique adapter delivery ID), and `x-lumin-signature` (`sha256=` plus HMAC-SHA256). Use the exported `mediaIngressSignature` helper, which binds exact raw bytes, the full canonical-JSON server-owned profile, timestamp and delivery. Object key ordering cannot change the binding. Changing the client, provider, app, account, connection, CDN host or enabled state changes the signature binding. Reusing a delivery cannot mint another proposal while its record exists. Expired historical signatures remain invalid after TTL deletion. Production intake also requires HTTPS at the transport boundary.

Every ingress route also requires the pre-authentication header `x-lumin-request-signature` (`src/platform/ingress-preauth.ts`): an HMAC over router, profile, binding, timestamp, delivery ID and the exact `Content-Length`, verified in constant time from the headers alone before the body is read and before the single in-flight slot is taken. A request without it is refused with 401 outside development and test (`LUMIN_INGRESS_ALLOW_LEGACY_BODY_SIGNATURE=true` is the named exception), a declared length above the cap with 413, and a busy slot with 429. The body signature `x-lumin-signature` is still verified afterwards and still binds the content. Any adapter that signs requests must send the new header before an ingress route is enabled; all ingress routes are off by default. A delivery id whose pre-authentication signature verified stays consumed for 600 s even when the body check later fails (only a 429 busy refusal releases it), so a captured header set cannot be replayed to hold the ingress slot; the adapter must use a new delivery id for every retry.

An accepted intake returns a proposal ID, plan hash, expiry and `AWAITING_HUMAN_REVIEW`; it returns no credentials and dispatches nothing to Meta. The authenticated operator reviews `/platform/media/review/{proposalId}`, including the client, account, digest, dimensions, AI declaration and a link to the adapter-controlled image. Review requires a current authenticated platform administrator or connection administrator with access to that client and the selected connection. Submission requires an HTTPS Secure HttpOnly SameSite cookie, signed session-bound CSRF value, exact origin and exact plan hash. Enrollment atomically consumes the proposal, creates the source MEDIA asset and its bounded grant, appends that asset to the selected connection, and records a `MEDIA_ENROLLED` control audit. The grant contains only the intersection of the existing root grants restricted to the reviewed JPEG draft/status/publish contracts for Instagram, or Page photo publishing for Facebook. It cannot increase tasks or actions. Drafting and publishing still require their own action approval.

Firestore `mediaProposals` uses the existing tenant-scoped repository and AES-GCM encrypted plan with authenticated identity binding. Configure the `expireTime` TTL field on that collection, as for `discoveryProposals` and `approvalRequests`. Runtime authorization checks expiry synchronously; TTL deletion timing never grants access. The durable proposal creation and control audit are transactional. No JPEG bytes, base64, pixel arrays, message content or credentials are persisted in proposals or audits. Asset and grant freshness is never renewed by review; original parent snapshots, current scopes, client status, operator roles, all parent grants and app-user lifecycle locks are rechecked before the atomic commit. Changed or revoked evidence requires new intake and review.

Current scope is JPEG single-image Instagram publishing and immediate Facebook Page photo publishing. Page publishing requires separately approved Facebook rights and a current authorized Page connection. The initial Page subset is URL-only and excludes AI-generated photos until a documented Page AI-label request contract is implemented. JPEG dimensions inherited from the reviewed Instagram decoder envelope are conservative local restrictions, not claimed Facebook API requirements. A Page photo receipt must contain the exact composite post ID before a POST asset is registered; a photo ID without that receipt is UNKNOWN and requires reconciliation without automatic retry. Video, carousels, mutable URLs, caller-supplied rights setters, public media hosting, and automatic renewal are not implemented by this intake. This module requires a separately configured approved immutable CDN adapter and a current authorized provider-specific Instagram or Page connection. Local tests establish engineering behavior; they do not establish a deployed CDN adapter, Meta approval, successful provider publication or owner acceptance.
