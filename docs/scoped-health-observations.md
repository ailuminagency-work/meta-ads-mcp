The seven client-scoped health tools report local recorded evidence only. They do not contact Meta, certify token validity, infer remaining provider quota, or establish staging acceptance. Current membership is checked again before returning results. Connection metadata is restricted to the authenticated operator and the selected client's registered READ bindings. Rate output is restricted to the corresponding credential bucket; only its effective backoff is returned, never other clients' usage.

`LUMIN_HEALTH_ENABLED=false` keeps durable failure recording disabled. Enabling it requires the reviewed `platform_health_events` scopeHash/timestamp descending index and seven-day expireTime TTL from the dry-run bootstrap plan. Failure records contain a hash of the client scope, tool name, uppercase reviewed reason, category, and timestamps. Arbitrary provider messages, credentials, customer content and recipients are excluded. Diagnostic storage failures preserve the original operation failure.

Webhook observations require the configured local signed-event inbox, fresh registered assets and grants, current recorded connections and an unlocked provider identity. Queries are bounded to ten authorized assets and one day, with at most 100 events per asset and explicit truncation. An empty or unconfigured inbox does not prove delivery is healthy. The recent-errors report includes bounded local diagnostic failures and uncertain/failed audited operations; it is not a complete provider incident ledger.

All seven tools are read-only. Their outputs distinguish unavailable observations, stale recorded inspections and unknown expiry. Production flags and cloud resources have not been changed as part of this engineering work.
