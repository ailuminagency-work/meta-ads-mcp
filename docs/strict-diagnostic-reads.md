# Strict diagnostic READ compatibility

Current official Meta Python SDK `adaccount.py` (Sep17,2026 `efd8423a2e595ea8d4c04eb824ce113f2f1d68cd`) declares `opportunity_score` as a float. The original account-only `ads_get_opportunity_score` now reads that exact field, not the unrelated `score` key used by the baseline handler. It reports missing/null as not provided; no recommendations, health guarantee or default zero is invented. Campaign mode remains outside this reviewed subset. The local finite0..100 bound is an explicit conservative validation policy.

`ads_get_errors` reads fixed account status/disable fields and fixed `effective_status`/`issues_info` on registered client ads only, through their registered advertiser closure. It does not discover or grant unrelated ads. The current SDK `ad.py` declares issues as `list<AdgroupIssuesInfo>`; current `adgroupissuesinfo.py` declares integer `error_code` and string `error_type`, `error_summary`, `error_message`, `level`, `mid`. Lumin deliberately excludes `mid`, projects bounded credential-safe issue text, and does not fetch URLs or recommendations. Local severity is a transparent interpretation of effective status. Bounded inventory completeness is relative to registered assets, never all provider ads or a complete account health certification.

Sources: [AdAccount](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/adaccount.py), [Ad](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/ad.py), [issue schema](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/adgroupissuesinfo.py). The shared Lumin USER/system-user `ads_read` requirement and current Marketing eligibility gate are conservative local requirements inherited from the verified strict read adapter, not an endpoint-specific minimum inferred from generated SDK schema.

The reviewed `ads_get_ad_dossier` subset uses at most six fixed reads: exact registered AD, account, campaign, ad set and creative, plus optional one-page unified-attribution AD Insights. The actual AD `creative{id}` must match its registered CREATIVE, and actual account/campaign/ad-set fields must match the authorized closed chain. Creative copy is bounded output only; provider source/image/landing URLs and raw nested specs are excluded. This closes a useful typed dossier read, not the baseline's media download/keyframe/targeting-description/auction-ranking variants: `include_media=true`, `include_targeting=true` and media delivery options still fail closed. Missing provider sections are not synthesized, and no image/video analysis is claimed.
