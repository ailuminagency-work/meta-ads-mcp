# Promoted-app event-type metadata

`marketing_list_app_event_types` is a default-off, read-only observation for one already registered promoted APP and its account. The deployment must separately enable `LUMIN_APP_EVENT_TYPES_ENABLED` and the app-promotion module, include `marketing.list.app_event_types` in the immutable approved profile, and obtain actual product-specific USER consent. No credentials are accepted as tool arguments.

The client rechecks actual account/app assignment and the exact approved store URL, then requests only `event_name` from `/{application-id}/app_event_types`, with a local bound of100 rows. It returns observed names and a completeness flag. It does not follow provider pagination. Descriptions, logged parameters, customer data, provider URLs and raw provider responses are withheld. A final completed READ checkpoint covers current membership, all recorded asset/grant ancestry, the selected encrypted credential, privacy/lifecycle locks and the captured deployment configuration before output.

Event-name availability does not establish app-event delivery, optimization eligibility, SDK installation, ownership, attribution configuration or permission to send events. A missing/denied provider response remains HOLD. The initial USER `ads_read`/`ads_management` pack is a conservative Lumin requirement; the inspected reference does not establish a universal minimum scope or app-role contract.

The official v26 [Application app_event_types edge](https://developers.facebook.com/docs/graph-api/reference/application/app_event_types/) and its linked [ApplicationAppEventTypes node](https://developers.facebook.com/docs/graph-api/reference/application-app-event-types/) were inspected on2026-10-16. The edge documents GET and excludes create/update/delete; the node documents event_name and separate descriptive/parameter fields. The pinned [official SDK Application implementation](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/application.py) corroborates the edge. These references establish a bounded API shape, not Lumin's actual app access or provider acceptance.
