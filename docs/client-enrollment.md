New-client onboarding is available only to a signed-in, current admin of an existing trusted tenant when `LUMIN_CLIENT_ENROLLMENT_ENABLED=true`. The protected browser path is `/platform/clients/new`. It uses a five-minute signed, same-origin, session-bound review with the exact current member revision. A successful submission atomically creates one client and its declared root assets, extends only that admin's client list, and writes a control audit. The same review cannot be replayed after the member revision changes.

This first step records IDs from the client's instruction. It creates no credentials, connections, grants, provider rights, verified business IDs, ownership or billing assertions. Meta's actual OAuth inspection must independently prove each selected asset before grants are enrolled. The administrator must configure the server-owned exact OAuth profile; a model or browser declaration cannot select arbitrary scopes or mint an app profile. WhatsApp preserves distinct business and messaging accounts and their exact phone parent closure. Instagram through Facebook requires its linked Page declaration; direct Instagram and Threads retain their own identity models.

The existing trusted tenant/operator must be installed through the separately reviewed deployment bootstrap. This route cannot create a tenant, add an operator, elevate roles or replace an existing client or asset. Initial business-owner and billing evidence, provider setup, and authenticated consent remain separate reviewed steps. No deployment or registry write was performed during candidate engineering.
