# Website Purchase custom conversion

`marketing_create_purchase_conversion` creates one definition for an explicitly registered client Pixel/account after a separate exact human approval. The server fixes website action source and PURCHASE category, with the documented AND rule: event equals Purchase and value greater than the approved positive threshold. No arbitrary rule, customer attribute, custom event, advanced rule, default revenue or delivery activation is accepted.

Current provider proof reads account/adspixels membership, Pixel id/is_unavailable and the bounded complete account/customconversions inventory. Missing source, unavailable Pixel, duplicate/malformed/paginated inventory or100 existing definitions prevent the POST. The provider remains the final concurrent capacity enforcer; this preflight is not an atomic Meta lock. Current local READ/mutation grants, independent client ownership/billing evidence and selected USER credential are revalidated before the single durable attempt. Unknown receipt or a present provider error marker prevents registration and does not permit automatic retry.

Successful atomic registration preserves the exact account/Pixel parents and immutable approved threshold/source definition. It proves creation provenance only, not an actual event, firing, policy availability, delivery or successful outcome. Future use must inspect current availability; Meta may flag prohibited definitions and returns is_unavailable true. The source declares Standard API access as a requirement; local conservative ads_read/ads_management plus dependency scopes do not certify provider minimum scopes or current app approval.

Primary evidence: the current [v26 Custom Conversion reference](https://developers.facebook.com/docs/marketing-api/reference/custom-conversion/) shows the exact Purchase/value rule, event_source_id Pixel, website action-source enum,100/account limit and numeric ID receipt; [account creation edge](https://developers.facebook.com/docs/marketing-api/reference/ad-account/customconversions/) and [official pinned SDK](https://github.com/facebook/facebook-python-business-sdk/blob/efd8423a2e595ea8d4c04eb824ce113f2f1d68cd/facebook_business/adobjects/adaccount.py) confirm current POST fields. Live reads/writes have not been performed. Synthetic native journeys exercise approval, fixed reads, one POST, registration, zero-egress foreign/capacity denial and unknown/error/replay behavior.

The threshold compares the provider event value as supplied. It is not an account-currency minor-unit budget and performs no currency conversion. Mixed-currency source semantics require separate review before use.
