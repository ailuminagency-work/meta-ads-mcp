# Official Meta Ads MCP comparison

Primary documentation was inspected in the browser on 2026-10-16. This is a documented-surface comparison, not an authenticated `tools/list` from Meta's hosted server and not a claim that Lumin has those permissions. The overview describes seven categories. Most category pages were updated July 14, 2026; the catalog page was updated September 7, 2026. Meta's public documentation names 86 distinct tools across the inspected tables, with `ads_get_ad_entities` appearing in two categories. Actual account rollout and server schemas remain independently unverified.

| Official category | Documented table entries | Lumin's bounded implementation and remaining differences |
|---|---:|---|
| [Creation and management](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-ad-creation-and-management) | 28 | Scoped account/entity/media reads, paused campaign/ad-set/ad creation, typed updates, separate AD-only activation, image/video creatives, limited audience creation, Instagram metadata, and private existing-ad preview engineering. Broad hierarchy activation, boosting existing Instagram posts, audience user upload/update/delete, and all discovery aliases are not certified equivalents. |
| [Reporting](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-comprehensive-reporting) | 7 | Fixed scoped Insights, existing context/trend/anomaly reads, account opportunity observations and asynchronous reports. Industry/auction benchmarking semantics remain unverified; Lumin does not manufacture benchmark or recommendation scores. |
| [Signals and datasets](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-signals-and-datasets) | 13 | Registered Pixel metadata, dedicated AdsDataset identity read, offline quality, custom-conversion metadata and fixed approved Purchase definitions. Official Event Setup Tool event/parameter CRUD concerns browser configuration, distinct from sending first-party CAPI events; Lumin has no certified equivalent CRUD. Generic Dataset discovery and health are also not interchangeable with Pixel observations. |
| [A/B tests and lift studies](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-abtests-and-conversion-lift-studies) | 7 | Registered study reads and a separately approved classic split test on two existing paused campaigns. Conversion lift creation, eligibility APIs, broader experiment updates and new study modes are not covered by that subset. |
| [Catalog management](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-catalog-creation-and-management) | 29 | Client-owned/client catalog inventory, product/feed/set metadata and assigned-user observations. Product/catalog/feed mutations, upload sessions, feed rules, event-source connection changes, and complete catalog health/diagnostics are not certified equivalents. The user's catalog scope is an explicit bounded asset-management layer, not a claim of full Commerce Manager control. |
| [Help and troubleshooting](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-help-and-troubleshooting) | 2 | Registered-ad error observations exist. Current Help Center search/retrieval semantics remain a separate required contract; unrestricted URL fetching is excluded. |
| [Activity logs](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-activity-logs) | 1 | Existing bounded account activity observations are narrower than the official tool's object/time/category/user filtering. Local mutation audits are separate evidence and do not replace provider history. |

The [official overview](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-overview) confirms the hosted endpoint and categories. Tool-name similarity is insufficient to certify parity: provider identity, schema, current account access, parent relationships, output privacy, mutation approval and actual returned facts must also match. This audit explicitly rejects a full-parity claim for the current candidate. Remaining engineering is tracked separately from credentials, app review and documented provider restrictions.
