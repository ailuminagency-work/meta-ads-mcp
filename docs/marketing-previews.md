# Private existing-ad previews

This default-off feature reads a registered existing ad using its selected USER credential. The reviewed Meta guide (updated June 16, 2026) explicitly requires a user token rather than a Page token: https://developers.facebook.com/documentation/ads-commerce/marketing-api/generatepreview . Lumin requires ads_read conservatively; documentation is not evidence that a particular client has access.

The MCP response contains a same-platform preview path and safe availability metadata. The signed Meta URL and provider HTML are never returned to the model, persisted, or logged. Opening the authenticated path performs a fresh exact AD/account/creative chain inspection and a fresh preview read. After completing the read, an atomic readonly checkpoint compares every original authorization dependency, the exact encrypted credential envelope used for the provider read, operator index, and platform/provider privacy/lifecycle lock before rendering. Provider HTML is parsed as one bounded iframe; the platform constructs its own sandboxed page and admits only the documented Facebook preview iframe endpoint with two opaque signature parameters.

LUMIN_PLATFORM_ENABLED and LUMIN_MARKETING_PREVIEWS_ENABLED must both be true, with HTTPS and configured session/encryption settings. Defaults remain off. Invalid flags fail startup. This feature does not create creatives, expose share links, activate ads, or send provider writes. Preview rendering still depends on the human viewer's current Meta session and ad-account role. Fixture tests establish local guards, not live Meta eligibility or visual acceptance.
