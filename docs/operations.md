# Operations and rollout gates

Flags default off: LUMIN_PLATFORM_ENABLED, LUMIN_PLATFORM_WRITES_ENABLED, LUMIN_PLATFORM_WEBHOOKS_ENABLED, LUMIN_PLATFORM_OAUTH_ENABLED, LUMIN_PLATFORM_MESSAGING_POLICY_ENABLED and LUMIN_PLATFORM_SIGNALS_ENABLED. Mutations additionally require AGENCY_WRITES_ENABLED=true. Invalid platform/webhook flag values fail closed. Webhook mounting requires both platform and webhook flags plus a trusted environment subscription/index configuration or reviewed injected dependencies.

Do not enable the feature in production until strict legacy migration, OAuth adapters, human approval issuance, fresh-grant refresh, registry bootstrap and host event runtime are reviewed and accepted. Disabling the platform flag restores the legacy route; disabling the write flags prevents platform mutations. No flag changes are authorized by this branch.

Webhook operations require Firestore queue indexes, expireTime TTL, a supervised retry scheduler, DLQ access, metadata-only monitoring and idempotent adapters. Claims reject expired events immediately even while asynchronous TTL deletion is pending. Retention defaults seven days and is bounded at thirty; optional encrypted payload storage is not enabled.

On ambiguous provider write, reconcile operation state using observed provider state before considering a new approval. Revoke affected connections/grants on ownership reassignment. Refresh freshness evidence under least privilege; never relax the freshness clock to keep a stale token working. Monitor counts/status/request IDs only; never customer messages, tokens or raw callback URLs.

First-party signal dispatch deduplication metadata has a fixed maximum retention of 90 days from the initial claim. Configure Firestore TTL on `expireTime` for the `platform_signal_dispatch` and `platform_signal_dispatch_audit` collection groups. State transitions preserve the original deadline and never extend it. TTL removal is asynchronous: a checkpoint still present after its deadline returns an explicit reconciliation HOLD on lookup, claim, or transition. The service never deletes or reclaims a stale checkpoint to enable a retry. After TTL removal, the original event is also outside the seven-day source-event freshness and encrypted-source retention policies; a trusted integration must never reuse an event identity for a new outcome. No automatic provider retry is permitted for UNKNOWN or ATTEMPTED outcomes.
