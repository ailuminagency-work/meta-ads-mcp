# Lumin Meta Platform candidate architecture

Status: isolated engineering candidate, HOLD for deployment and real-provider acceptance. No production rollout or registry migration is performed by this branch.

The existing MCP endpoint and142 legacy tools remain unchanged when LUMIN_PLATFORM_ENABLED=false. Strict mode installs a public-registration guard before legacy registration. It migrates12 bounded Ads READ adapters and3 minimal PAUSED creation adapters; the other127 legacy handlers fail closed pending exact endpoint/reference/projection/workflow certification. Product contracts and legacy tools both appear in the canonical capability report. Unsupported or blocked implementation is distinguished from an unsupported Meta API.

Authenticated operator identity comes from the existing verified request context. A server-owned operator index resolves tenant membership. Client identifiers are checked against active membership, recognized roles and client state. Every direct and recorded indirect reference is resolved through same-client/provider/app parent closure, with cycle and freshness checks. READ evidence lasts at most60 minutes; mutation evidence at most5 minutes. Credentials use mandatory versioned authenticated encryption and deterministic narrow connection selection without fallback.

Execution validates typed input, binds canonical endpoint/body, resolves authorization, evaluates classes, consumes an exact one-time approval with PREPARED audit, mints an opaque permit, revalidates current records and final-moment eligibility, decrypts internally and claims one mutation attempt immediately before network. Transports are fixed-host, bounded, sanitized and do not automatically retry mutations. Uncertain provider outcomes are UNKNOWN and require reconciliation.

The paused Ads subset creates AUCTION awareness/traffic campaigns, website/link-click geographic adsets and ads referencing existing registered creatives. Complex targeting, new creatives, promoted objects, reserved buying, lifetime budgets, copies and activation remain HOLD. All three creation types require human approval; budgets additionally classify WRITE_BUDGET. Root ownerBusinessId, official billing evidence and Client.verifiedBusinessIds must establish client ownership. Successful created-ID provenance commits asset, inherited grant, connection revision and terminal audit atomically; rejection is PARTIAL or reconciliation HOLD. Subsequent steps need fresh independent authorization; there is no automatic campaign chain.

Product clients enforce endpoint contracts, selected credentials, projections and shared rate controls. Capability metadata uses a request-local read-only memoized registry view; it never mints permits, decrypts credentials, sends provider calls or treats unapproved writes as available.

Optional deployment-owned OAuth profiles use protected connection/client selection and callback routes, immutable profile snapshots, pure adapter validation before consent, atomic nonce challenges and actual token inspection. Facebook Marketing supports only core READ and3 paused-create consent packs; Business and Threads support their narrow verified READ packs. Token enrollment does not establish manage role, access tier, App Review or billing ownership. Unsupported adapters remain HOLD. Dynamic profile administration requires future transactional profile revision support.

The human approval page authenticates the approver, enforces role/client/Origin/signed CSRF/expiry, displays exact escaped content and rechecks plan/revisions. MCP prepares and observes approval requests but cannot approve them. Messaging policy uses a dedicated recipient-HMAC key and durable trusted evidence. Signed webhook ingress normalizes and durably enqueues before optional consumer and messaging hooks; opaque proof binds raw body/events/subscription. Workers use fenced leases, reauthorization, retries and DLQ. LeadGate remains an optional adapter, not a core dependency.

Remaining rollout gates include reviewed production bootstrap, trusted profile/evidence configuration, provider access/ownership verification, supervised evidence refresh, webhook indexes/TTL/scheduling/monitoring, peer/governor review, staging rollout and consenting external-client acceptance. Fixture tests prove local invariants only.
