# Lumin Meta Platform candidate architecture

Status: local engineering candidate. Production deployment and staging acceptance have not been authorized or performed. Exact tool counts come from the regenerated inventory at source freeze; historical counts do not describe this evolving candidate.

The existing MCP endpoint and original142 registrations remain available in baseline mode when LUMIN_PLATFORM_ENABLED=false. Strict mode installs a registration guard and routes individually migrated original names through client-scoped adapters. Unmigrated names fail closed with explicit implementation gates. Canonical product contracts appear alongside original tools in capability reports. An unavailable implementation is not automatically an unsupported Meta API.

Verified request identity resolves a server-owned operator index and active tenant membership. Every operation names one client. References require the recorded same-client/provider/app parent closure, current grants and product-specific credentials. Cycles, foreign references, revoked records, stale evidence and ambiguous selection fail closed. Credentials remain encrypted and decrypted only inside authorized transports; metadata tools never return them.

Execution binds typed input, endpoint, body, actor, client and record revisions into an exact plan. Protected human approval uses authenticated roles, signed same-origin CSRF and bounded validity. MCP can prepare and inspect requests but cannot approve. Execution consumes approval once, audits the attempt, revalidates before egress and sends a bounded fixed-host request. UNKNOWN outcomes remain quarantined. Created resources, narrow grants, connection revision and terminal audit commit atomically or report PARTIAL/HOLD.

Marketing includes reviewed paused creation, selected targeting, CBO, registered image/video sources, Instant Form lead chains, audiences and AD-only controls. Each step has fresh approval and current relationship/financial evidence. A supervised paused-ad batch records an immutable ordered proposal, links separately approved single-ad steps and stops on uncertainty. It does not automatically activate delivery. Account access, a human Business-owner artifact and client-owned billing are distinct evidence gates; a GET alone never establishes ownership.

Marketing app-install support wraps the existing campaign tools rather than introducing another campaign engine. An immutable deployment binding fixes the promoted app, store URL, operating system, account and Page. Actual app/account/store inspection precedes protected human APP enrollment. Separately approved campaign, ad-set, creative and ad creation remain paused. Supervised renewal rechecks the exact registered closure without changing historical ownership, financial evidence or app assignment evidence. Live app-event delivery and optimization eligibility remain provider gates.

Private video inspection proves actual account membership and, for creative inspection, the provider's exact creative/video relationship. The service downloads only a bounded authenticated provider-returned Meta CDN source, decodes real JPEG samples privately, and returns images only after a final atomic current-authority/credential check. Registered Page, thumbnail and other required ancestors remain in the authorization closure. Sampling offsets are requested seek positions, not measured presentation timestamps; no transcription or semantic analysis is claimed.

Catalog campaign diagnostics combine an explicitly registered Marketing ad-set with an independently authorized same-client Business catalog. Fixed reads compare actual promoted-object references and bounded Advantage state fields; one final atomic checkpoint covers both credentials and complete authority closures. A matching ID does not establish Advantage eligibility or delivery. Client invoice reads require current actual Finance EDITOR/ANALYST evidence, authorized owned accounts and independent client financial evidence. Only metadata within the requested dates is returned; an invoice touching an unapproved account is withheld in full.

CRM conversion-lead ingestion links a verified signed Meta lead event, authorized Graph lead metadata and a signed first-party CRM transition. Source storage remains encrypted and purpose scoped. A permanent minimal HMAC no-resend barrier survives detailed-journal TTL, source erasure and uncertain provider outcomes. Changing the HMAC namespace or funnel requires an explicit migration; erasure never silently releases a resend. Credential compatibility and provider event acceptance are separate checks.

Product-specific OAuth profiles are immutable deployment configuration. Protected selection, atomic challenges, code exchange and actual inspection establish narrow grants. Separate Instagram/Threads app-user identities remain bound to privacy locks. Token renewal does not renew permissions, asset tasks, source rights, ownership or dashboard eligibility. Human observations have explicit lifetimes and exact tool allowlists.

Media intake uses signed scoped sources, bounded validation and human enrollment. JPEG/MP4/MP3 and document paths retain their declared limits; PDF intake is not a malware certificate. Publication separates enrollment, container creation, readiness, quota and separately approved publish. Customer content, lead answers and recipients remain purpose/client restricted. Frontend oEmbed renders tokenless reviewed embeds outside model outputs.

Webhooks verify signatures and durably enqueue bounded normalized metadata. Fenced workers use scoped leases, idempotency, retry limits and DLQ controls. Trusted messaging evidence enforces windows and opt-in. First-party conversions bind consent, event identity and source truth; dispatch claims prevent automatic resends. LeadGate remains optional.

Optional paid research has an empty deployment-owned adapter registry, human cost review, monthly client reservation and single attempts. Unresolved financial checkpoints survive personal job erasure; current administrators reconcile free cost metadata without recovering private queries or paid retry. No vendor or research spend is enabled by the infrastructure budget.

Staging preparation is a pure dry run: IAM, indexes, conditional TTL, registry closure and disabled flags are review artifacts only. Privacy tombstones, unresolved phone claims and unresolved financial checkpoints cannot expire to unlock retries. Exact-candidate tests, build, secret checks and independent review precede staging approval. Provider consent, App Review/access tiers, ownership/billing, infrastructure installation and live journeys remain separate gates.
