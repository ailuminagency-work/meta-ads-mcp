# Independent Instagram token continuity

The operational human review supports `REFRESH_TOKEN_ONLY` for independent Instagram Login. It is deliberately separate from permission and asset-grant renewal. Meta's current [Business Login guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/business-login), checked in the browser on 2026-10-16, documents GET `/refresh_access_token?grant_type=ig_refresh_token&access_token=...`, a long-lived token at least 24 hours old, a valid unexpired token, and the basic permission. Its receipt contains only access_token, token_type and expires_in. It does not prove the current full granted permission pack.

The implementation checks the exact deployed Instagram app and existing credential/connection, trusted `tokenIssuedAt`, current app-scoped user and professional-account identities through the fixed `/v26.0/me` response, then durably claims one separately human-approved refresh. It checks the same identities again for the returned token. Secrets stay in encrypted credential storage; no token is returned to MCP or the browser. The deployment must explicitly set `INSTAGRAM_API_VERSION=v26.0`.

Successful completion changes only encrypted token, token expiry, trusted token issuance time and connection revision. It preserves connection `verifiedAt`, scopes, every asset/grant timestamp and expiry, tasks, source rights and ownership. Expired or stale grants remain expired or stale. Current permission verification and usable asset authority require fresh ordinary OAuth consent/code exchange; this adapter never guesses a permission endpoint, calls Facebook debug_token for Instagram, or copies stored scopes as fresh inspection.

Connections without trusted issuance metadata require reauthorization before token-only refresh. Unknown provider outcomes permanently consume the human command and disable local access, with no automatic retry. Provider-side revocation remains a human Meta action or the signed privacy callback workflow. No live refresh or deployment was performed by these tests.
