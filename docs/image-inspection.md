# Current client advertising JPEG inspection

Local engineering candidate; no staging deployment or real Meta image access has been certified. LUMIN_IMAGE_INSPECTION_ENABLED defaults false.

marketing_inspect_image accepts one already registered AD_IMAGE hash. marketing_inspect_creative_image additionally requires an exact registered creative and explicit registered image_hash. The current creative/account/image relationship is verified with a fixed selected-credential GET; only the documented top-level image_hash variant is supported. Photo-data, carousel, implicit ad resolution and recursive URL extraction are not substituted.

The account image query uses documented hashes filtering with exactly one hash and fields id,account_id,hash,url,width,height,status. The response must contain one complete ACTIVE row whose account/hash match current registry authority. Optional provider id is a bounded opaque string, never an authority input. A conservative USER ads_read consent pack and separately reviewed client access are admission boundaries, not universal endpoint-minimum claims. OAuth can enroll account roots only; a newly approved image upload inherits only current matching parent capabilities. Ordinary account-only OAuth does not fabricate grants to existing image or creative leaves.

Only the authenticated provider-returned HTTPS fbcdn.net source can be downloaded, using pinned public DNS, no redirects, an eight-MiB byte cap and a finite request deadline. Caller URLs are excluded. Selected credentials are never forwarded to the CDN or placed in the download URL. The actual JPEG is decoded/reencoded inside a bounded worker, with four-megapixel/4096-dimension limits, a ten-second deadline and at most two active decoders. Reencoding strips source metadata; the returned preview contains actual decoded pixels, not generated media. A private WeakMap digest proof binds the decoder result to the exact downloaded bytes and is rechecked before copying the output.

Every provider step and post-download/decode check uses the current selected credential, client grants, identity locks, current manual access, rate controls and v26.0 gate. The completed READ has a sealed final Memory/Firestore authorization checkpoint covering all current parents, encrypted credentials, members/global indices and provider-subject locks. No image block is returned until that checkpoint and the final synchronous flag/version checks pass. Creative closure may include its Page, lead form and video ancestor; revoking any required authority withholds the result.

The strict original ads_get_creative_media alias requires client_id, creative_id, image_hash and optional connection_id. Its broad legacy URL/video/carousel/ad-resolution options are rejected in strict mode. Flag-off baseline registrations are unchanged. No image URL, token, raw EXIF/comment metadata or semantic/paid analysis is returned or persisted.

Primary verified schema/transport evidence: pinned official Meta Python SDK efd8423a2e595ea8d4c04eb824ce113f2f1d68cd files adaccount.py (GET /adimages and hashes list), adimage.py (fields and string id), adcreative.py (account_id/image_hash). The SDK establishes supported fields and transport; actual external-client access remains a staging proof gate.
